Four read-only audit agents ran in parallel: core C speed and core C bugs
(csearch.c, movegen.c, eval_c.c, Constants.c/.h, NNUE/nnue.c), and speed and
bugs everywhere else (cengine.py, engine.py, cuci.py, lib/, match.py,
battle_worker.py, NNUE/*.py, testing/sprt.py, scripts/, selftest.py). Every
finding was re-run before anything was changed; a finding nobody could
reproduce was not fixed.

**State after the hunt:** main at `7701225`, bench **593,598** (every toggle
off), csearch abi **47**, selftest passing. A previous hunt on 07.11.2026
(49 fixes, abi 44) is not repeated here.

All numbers come from one Apple Silicon Mac (arm64), which was under heavy
unrelated load throughout (load average 14 to 36). Wall-clock NPS from it is
not a verdict; x86 is unmeasured for everything below.

## 2. Bugs in the core C

Clean: ASan+UBSan bench (0 reports), about 9,000 sanitized random searches
(standard, Chess960, hmc 90 to 130, timed), TSan at Threads=4 (0 reports; a
deliberately non-atomic store gave 216, so the check has teeth), 4.86M NNUE
incremental-vs-refresh checks (0 bad), movegen vs python-chess on 715k
positions (0 mismatches), ply-bound stress under ASan, 399 root mates
cross-checked.

The real findings all change search decisions, so each is a **default-off
toggle** (class attribute in cengine.py, setter in csearch.c, fingerprint,
uci banner, shim in `NNUE/shims/`). Bench is 593,598 with each one on.

| Toggle | Issue | Reproduction, off vs on | Commit |
|---|---|---|---|
| `PROBCUT_MATE_FIX` | A confirmed ProbCut returns `v - (pbeta - beta)` for mate scores too: a fake mate distance (29797) that parent TT entries carry as a mate | 2,376 such returns over 311 WAC positions at 0.25 s; 120 WAC positions at d9: 2,432,137 vs 2,423,791 nodes | `ee2e9e4` |
| `TT_MATE_R50` | TT mates cut regardless of the 50-move clock (the key has no clock, entries stay warm all game) | Children of `8/7k/1p6/p6K/P7/8/8/4Q3 b - - 97 120` searched at hmc 1, then the root: b6b5 (mated in 3) vs h7g7 (draw) | `442dd2e` |
| `NULL_R50_GATE` | The null move hands its child a 50-move clock of 0, hiding the 50-move draw in null subtrees | `1kr5/8/7n/4p3/4P2p/1P5P/4B3/4K3 w - - 95 35` d14: e2c4 at -439 vs e1d2 at the draw score | `7701225` |

All three fire rarely (near hmc 90+ or on ProbCut mates), so a 10k-game
screen is expected to read flat. **Decided 21.11.2026:** `PROBCUT_MATE_FIX`
(`d6ffc53`) and `TT_MATE_R50` (`a267a67`) are on by default without an A/B,
as score-correctness fixes (both are guards Stockfish has). `NULL_R50_GATE`
stays off: unlike the other two it removes pruning (no null move at hmc
>= 90) in long endgames, so it is a search trade, not only a correctness
fix. Screen command, one toggle at a time (about 14 h for the
full 10k games, estimated from bench NPS, not measured):

```bash
python3 match.py NNUE/shims/engine_null_r50_gate.py cengine.py 5000 --nodes 1750000 --workers 0 --sprt
```

`NULL_R50_GATE` is the cheap form (no null move at hmc >= 90). The principled
form carries a second, 50-move-only clock through the null move; build it if
the gate earns its place.

**Left open (policy):** at `7k/8/5K2/8/8/8/8/1Q6 w - - 98 80` the engine
plays b1h7, giving the queen away, because material-dependent contempt
scores the KvK draw (0) above a draw while ahead (-50). Result-neutral
wherever the arbiter adjudicates at hmc 100.
